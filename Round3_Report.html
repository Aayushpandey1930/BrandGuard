Executive Summary

BrandGuard helps teams verify promotional and customer-facing copy against verified brand guidance before publication. For Round 3, we focused rigorously on delivering the exact three commitments named at Round 2, closing all loose ends, solidifying robustness so the application holds up without guidance, and ensuring friction-free deployment.

1. Delivery of the Three Round 2 Commitments

We committed to three specific improvements at the conclusion of Round 2. Exactly those three have been engineered, integrated, and verified end-to-end:

Committed Improvement Implementation Details User Experience Impact Status
1. Persistent Sessions with SQLite Upgraded backend storage engine in backend/storage.py from fragile flat-file JSON to SQLite with Write-Ahead Logging (WAL) and automatic schema initialization. Added full lifecycle session and activity event storage. Sessions, reviewer comments, status choices, and audit logs persist reliably across restarts without corrupted states. Delivered
2. Custom Brand Profile Upload Implemented BrandProfileUpload.tsx component. Allows pasting custom JSON guidelines or uploading .json rule files with schema validation, reset controls, and instant rule binding in checker.ts. BrandGuard is no longer locked to fictional Northstar Coffee; any team or judge can test their own organization's voice, terms, and claims in seconds. Delivered
3. Inline Tracked-Changes View Engineered TrackedChangesView.tsx providing an intuitive dual-view: an annotated draft and live preview. Triggered text is highlighted in amber/red, accepted changes in green, and dismissed findings in neutral strike-through. Reviewers and writers see the concrete contextual visual diff within the document rather than inspecting disconnected replacement strings. Delivered

2. Finished Features & Closed Loose Ends

  • Full Action Lifecycle: Each finding supports Accept, Edit before applying, Dismiss, and Reopen. No interactive controls are dead-ends or decorative.
  • Two-Way Decision Making: Final decision supports both Approve and Request Changes with required/optional reviewer comments, logging explicit timestamps into the audit log.
  • Dual Execution Mode: The client-side TypeScript engine runs completely standalone in the browser (zero server dependency for judges), while simultaneously supporting seamless backend connection when the FastAPI + SQLite server is running.
  • No Faked AI: When OpenAI credentials are absent, the application explicitly states tone analysis is unavailable rather than fabricating synthetic compliance scores or hallucinating AI metrics.

3. Robustness & Fault Tolerance (Holds Up Without Author)

A judge will paste unexpected text, hit refresh, click buttons rapidly, or test edge cases. BrandGuard has been engineered to never break or hang:

  • Boundary Input Handling: Empty drafts, whitespace-only inputs, and strings exceeding 5,000 characters trigger graceful validation messages; submit buttons auto-disable with clear feedback.
  • State Preservation: Uploaded brand profiles and draft review state safely handle page refreshes and browser resets with default fallback profiles.
  • Double-Click and Concurrent Action Protection: All submit buttons implement distinct loading, spinner, and disabled states during asynchronous operations.
  • Schema Validation: Custom brand profile uploads parse safely with error catches; malformed JSON informs the user of syntax errors instead of crashing the UI tree.

4. Polished, Focused Interface

  • First-Minute Judge Usability: From the initial landing screen, a judge can click "Try sample review", see flagged findings with clear explanations, apply fixes, approve, and review the audit trail in under 60 seconds.
  • Restrained Visual Design: Uses a calm slate and navy palette, clear hierarchy, accessible contrast ratios, and zero distracting animations or mock corporate marketing badges.
  • Responsive Layout: Tested across viewports from mobile (375px) single-column stack to desktop (1440px) side-by-side inspection cards.

6. Reproducible Documentation & Deployment

Anyone can clone the repository and run the application locally within two minutes, or open the live deployment immediately:

Live Production Link: https://brandguard-ochre.vercel.app

To clone and run locally:

  1. git clone https://github.com/Aayushpandey1930/BrandGuard.git
  2. cd BrandGuard/frontend
  3. npm install && npm run dev → Open http://localhost:5173
  4. (Optional backend): cd ../backend && pip install -r requirements.txt && uvicorn main:app --reload
